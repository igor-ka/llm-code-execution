# Spec: adopting `acb` as consumer #1

Epic: [#210](https://github.com/igor-ka/llm-code-execution/issues/210) · Status: **all questions
answered — ready to plan**

Stack, commands, project layout and testing strategy are not restated here; they live in
[`CLAUDE.md`](../../CLAUDE.md) and [`README.md`](../../README.md). The toolkit being adopted is
[`igor-ka/acb`](https://github.com/igor-ka/acb), specified in
[`2026-08-26-sdlc-template.md`](2026-08-26-sdlc-template.md), whose decisions D1–D15 are
referenced by name.

## Objective

Make this repository the first real consumer of `acb`, so that the process it originated can be
updated *from* here and *into* here like any other.

That was D1's whole argument: this is the repository with the most activity, so it is where
improvements are discovered, and a one-way extraction gives them no path upstream. Everything
built in `acb` so far is arranged to be correct. **Nothing has demonstrated it.** The empty-diff
test is the demonstration, and it can only run here.

Done means three spec criteria that no work so far could reach:

| | From the toolkit spec | What it proves |
| --- | --- | --- |
| **SC1** | `acb pull` here produces a diff touching only `.acb.json` | The carried/generated boundary is drawn correctly |
| **SC10** | The five required check names survive unchanged | Adoption did not silently break every merge |
| **SC11** | `docs/sdlc.md` splits without losing the `SDLC docs` contract | The process document survives becoming carried |

## Context — what exists today

Grounding for the boundaries below; no design implied. Verified against the tree on 2026-08-29.

1. **`acb` is public and at `9cabf39`.** Its `carried/` tree holds 25 files, generalised and free
   of any identifier from this repository, and `tests/carried-purity.test.sh` keeps them that way.

2. **The five required checks are live**: `Backend checks`, `Frontend checks`, `SDLC docs`,
   `PR shape` and `Terraform checks`, in the `Protect main` ruleset (id `17055903`) alongside
   `copilot_code_review`, `required_linear_history` and thread-resolution. The `infra` component's
   check is named `Terraform checks` — the directory and the check name already disagree, which is
   why `.acb.json` carries `id` and `checkName` separately.

3. **The three `verify.sh` scripts do not satisfy the conformance contract**, on all three counts:
   - functions are `install()`, `lint()`, `test_()`, `docker_()` — not `target_<name>()`;
   - an unknown target exits **2**, where `check-conformance.sh` requires **64** to tell
     "unknown target" from "declared but unimplemented";
   - `test_()` and `docker_()` already carry a trailing underscore to dodge the `test` builtin —
     the same collision `target_` solves, solved differently first.

   This is the sharpest finding in the spec and it cuts both ways: the contract was modelled on
   these scripts and does not fit them.

4. **The carried skills have lost this repository's specifics**, deliberately (D5, and ACB-3).
   Gone from them: the backend/frontend command table, the `HistoryStore` contract-suite note, the
   `DATABASE_URL` self-skip trap named against `src/history/**`, and the sensitive-path list
   `backend/src/{auth.ts,history/**,sandbox/**}`. Adoption replaces the local skills with the
   carried ones, so that content has to land somewhere or it is simply lost.

5. **Two deployment suites were evicted from the carried `sdlc-docs.yml`** —
   `deploy-cloud-run.test.sh` and `verify-deployment.test.sh`. They were lodging there because
   their own workflows gate themselves and never run on a PR that edits them. Adoption takes the
   carried workflow, so they need a host or they stop running.

6. **`docs/sdlc.md` is 903 lines here and 699 in `carried/`.** The difference is the extracted
   worked example (119 lines) plus 85 lines of Cloud Run and stack-specific material removed in
   ACB-3. Adoption does not merely split this file — it *replaces* it with a shorter, generalised
   one and moves what was cut into local documents.

7. **`SKIP_DOCKER` and the `docker` target are referenced outside `verify.sh`** — in `CLAUDE.md`,
   `README.md`, `docs/sdlc.md`, and the CI workflow. The D5 renames are not confined to the
   scripts.

## Boundaries

**In scope**

- `.acb.json` declaring three components (`backend`, `frontend`, `infra`) with their existing
  check names, targets and runner.
- Replacing the local gate scripts, gate workflows and skills with the carried copies.
- **The D5 renames** — `docker`→`package`, `fmt`→`format`, `SKIP_DOCKER`→`SKIP_PACKAGE`, and
  `infra`'s `init`→`install`, `validate`→`lint` — everywhere they appear, not only in `verify.sh`.
- Splitting `docs/sdlc.md` into the carried process document and a local worked example.
- Rehoming the two evicted deployment suites.
- Preserving this repository's specifics that the carried skills no longer carry (OQ1).
- **A change to `acb`'s `check-conformance.sh`** — function discovery, and failing loudly when it
  finds none (D5). This reopens merged work in the toolkit, deliberately.
- **A sixth required check, `Deploy scripts`** (D6), and the ruleset edit that goes with it.
- `scripts/apply-ruleset.sh` and a generated `.github/ruleset.json` that reproduces the live
  ruleset — including `copilot_code_review`, which no earlier version of the template had.
- Setting `ACB_DEPENDABOT_ECOSYSTEMS` to `npm_and_yarn`.
- **Proving SC1**: `acb pull` produces a diff touching only `.acb.json`.

**Out of scope**

- **Changing what any check does.** Adoption is a re-housing, not a re-design. If a target's
  behaviour changes, that is a separate change with its own review — otherwise a green build after
  adoption proves nothing about adoption.
- **The worktree library** (`lib/worktree.sh`, D12). Deferred with the toolkit's own worktree
  slice; `scripts/worktree-new.sh` stays exactly as it is.
- **The deployment layer.** `deploy-cloud-run.sh`, `verify-deployment.sh` and `infra/**` stay
  local and uncarried, as the toolkit spec's Boundaries say.
- **Proposing anything upstream.** Improvements found during adoption are noted, not sent; a
  `propose` mid-adoption would move the target while SC1 is being measured.

**Non-goal.** This is not a cleanup pass. Anything that would be worth doing regardless of `acb`
is a separate change, because it would otherwise hide inside a diff whose whole purpose is to be
*empty on the second run*.

## Success criteria

1. **★ The empty-diff test.** After adoption, `acb pull` in this repository produces a `git diff`
   touching only `.acb.json`'s recorded commit. Any other hunk names a file in the wrong bucket.
   This is the criterion the whole toolkit was built to be measured by, and the only one that can
   distinguish a design that is arranged to be right from one that is.
2. **★ The five existing required check names are unchanged, and exactly one is added.**
   `Backend checks`, `Frontend checks`, `SDLC docs`, `PR shape` and `Terraform checks` survive
   verbatim; `Deploy scripts` joins them (D6). Verified against the **live** ruleset, not against
   the generated document. A rename blocks every merge until the ruleset matches, and "we also
   renamed one while adding one" is exactly how that goes unnoticed.
3. **★ Nothing that ran before stops running.** Every target, every self-test and both evicted
   deployment suites execute after adoption. A check that quietly stopped running is the failure
   mode this repository has already shipped once.
4. `scripts/check-conformance.sh` passes for all three components.
5. `acb status` reports `behind: 0`, `ahead: 0`, `drift: none`.
6. The generated `.github/ruleset.json` matches the live ruleset rule-for-rule, `copilot_code_review`
   included.
7. `./verify.sh` is green in all three components, with the renamed targets.
8. `docs/sdlc.md` still satisfies its own `SDLC docs` gate: the PR that changes it updates it.
9. No content identified in Context 4 is lost — each item is either in `CLAUDE.md`, a local
   document, or explicitly recorded as dropped.

## Decisions

**D1 — Adoption is re-housing, never re-design.** The temptation during a move is to fix things
noticed along the way. Every such fix makes the adoption diff harder to review and weakens SC1,
which depends on being able to say "everything here is either carried or declared". Improvements
are recorded and land separately.

**D2 — The live ruleset is the reference, not the template.** The template was already wrong once:
it was written from memory and missed `copilot_code_review` and `required_linear_history`. Adoption
generates the document, diffs it against `gh api repos/…/rulesets/17055903`, and reconciles toward
*the live one*, since that is the configuration known to work.

**D3 — Carried files are copied, never merged.** If a carried file needs a local change, that is a
signal the boundary is wrong, and the fix is either to propose the change upstream afterwards or to
move the varying part into `.acb.json` — never to keep a local edit, which SC1 would then fail on
forever.

**D4 — This repository's specifics get two homes and one list.**
`CLAUDE.md` takes anything a carried skill now refers to *by name* — the sensitive-path list and
the component/command table — because those skills say "`CLAUDE.md` names those paths" and that
sentence has to be true. A new `docs/testing-notes.md` takes the teaching content: the
contract-suite pattern and the self-skip trap. Anything in neither goes in an explicit **dropped**
list in the pull request body, so a reviewer can object to a loss rather than discover it later.

**D5 — The contract flexes on naming; the scripts flex on the exit code.**
Context 3's mismatch is split rather than paid by one side. `check-conformance.sh` **discovers**
the target function, trying `target_<name>`, then `<name>_`, then `<name>`, in that documented
order — and **fails loudly when it finds none**. That last part is the fix that matters
independently of which convention wins: a patch that silently inserts nothing produces an
assertion that passes vacuously, which is the exact defect this check exists to catch and which it
has already exhibited once.

The three `verify.sh` scripts change `exit 2` → `exit 64` for an unknown target — one line each.
That is not churn for its own sake: with 2 for both "unknown" and "not implemented", conformance
cannot tell a target that exists from one that does not, and would report a missing target as
dispatching. No function is renamed, which keeps D1 intact.

**D6 — The evicted deployment suites get their own required check.**
They currently lodge inside `SDLC docs`, which *is* required — so today they gate, and a
non-required job would silently downgrade that. `Terraform checks` is wrong by subject and
`Backend checks` muddles a job that already means something. So: a `Deploy scripts` job, added to
the ruleset's required list. A sixth required name is normally an expensive thing to add; here the
ruleset is being regenerated anyway, so the marginal cost is one line and the alternative is a
check that quietly stops gating.

**D7 — Three pull requests.**
1. **The renames** — `docker`→`package`, `fmt`→`format`, `SKIP_DOCKER`→`SKIP_PACKAGE`,
   `init`→`install`, `validate`→`lint`, everywhere they appear. Independently valuable, depends on
   nothing in `acb`, and shrinks the two that follow.
2. **The carried swap** — gate scripts, gate workflows, skills, the `docs/sdlc.md` split, D4's
   rehoming, and D6's new host.
3. **The generated layer** — `.acb.json`, `ci.yml`, `ruleset.json`, `apply-ruleset.sh`, the
   `ACB_DEPENDABOT_ECOSYSTEMS` variable, and **SC1 measured here and only here**.

SC1 is not measurable until everything is carried, so it is the third PR's acceptance criterion
alone. The first two carry a weaker obligation that is still absolute: the five existing checks
stay green throughout.

## Residual risk

- **This is the largest single change to this repository, and it is not optional.** It renames two
  targets and an environment variable across four file types, replaces thirteen skill files,
  swaps five gate files, and rewrites a 903-line document under an active CI contract — all while
  five required check names must not move.
- **SC1 can be satisfied trivially and wrongly.** Declaring fewer files carried makes the diff
  smaller and the test greener while transferring less. The count is the guard: 25 carried files,
  every one of them present.
- **D5 reopens merged work in `acb`.** The conformance change lands there, is reviewed there, and
  must be pulled here before the third pull request can pass SC1 — so the two repositories are
  briefly coupled in a way nothing else in this plan is. Sequencing it early is the mitigation.
- **Copilot review has never run on this repository's PRs under a generated ruleset.** The rule is
  present in the live one and in the template; nothing has yet verified that applying the generated
  document leaves it enabled rather than resetting it.

## Not yet decided

Whether this repository ever proposes its improvements upstream, or whether `acb` is maintained

actually used, and therefore whether R2 is a live path or a theoretical one.
