# Adopting `acb` as consumer #1 — Implementation Plan

**Goal:** Make this repository the first real consumer of `acb`, so the process it originated can
be updated *from* here and *into* here like any other — and prove it with the empty-diff test,
which is the only check that can tell a design arranged to be correct from one that is.

**Architecture:** Three moves in order. First the **contract**: the three `verify.sh` scripts adopt
the canonical target vocabulary, the `exit 64` unknown-target code, and a `--targets` introspection
arm — all local, all independently valuable. Then the **swap**: twenty-five carried files replace
their local originals byte-for-byte, `.acb.json` supplies the variation they read at run time, and
the material the carried copies generalised away moves into three local documents. Last the
**generated layer**: the ruleset document, its apply script and the auto-merge allow-list, followed
by the measurement — `acb pull` must change nothing.

**Tech Stack:** bash 3.2, `jq`, `gh`, GitHub Actions, Terraform 1.15.8, Node 22. No new dependency
is introduced by this plan.

**PR boundaries:** Four, and the first is in a different repository.

  and to discover; the drift check learns that a repository has more than one workflow file; the
  auto-merge gate's verdict expression stops indexing an array with a string; and the carried
  process document stops telling every consumer to edit a file some of them must not edit.
  Closes the child *acb: fix what adoption found*.

## The structural problem the spec did not reach

`docs/sdlc.md` is a **carried** file — item 18 of the MANIFEST, byte-identical in every consumer.
The `SDLC docs` gate requires that a pull request touching a watched path *also touches
`process.doc`*. Point `process.doc` at `docs/sdlc.md` and the two rules collide:

> Every change to `backend/verify.sh`, `scripts/`, `.github/workflows/` or `.claude/skills/` must
> edit a carried file. Editing a carried file makes `acb status` report `ahead: 1` and makes
> `acb pull` produce a non-empty diff. **SC1 can then never pass again.**

The alternative — reaching for `[skip-sdlc-sync]` on the routine case — turns the visible escape
hatch into the normal path, which is the failure mode this repository already fixed once (the job
sat un-enforced from #53 until 2026-08-09).

**The plan therefore sets `process.doc` to `docs/sdlc-local.md`**, a new local document holding
this repository's own process specifics — the ones the carried copy generalised away. The reasoning
is that the carried `docs/sdlc.md` is by construction the *shared* half of the process, and a change
to `backend/verify.sh`'s `package` target has nothing to say in it. The document a local process
change actually invalidates is the local one, and that is the document the gate should demand.

SC11 — "`docs/sdlc.md` splits without losing the `SDLC docs` contract" — is met in this reading: the
contract survives, pointed at the half it can still bind.

**Decided, 2026-08-29, after the staff-engineer review.** The alternatives were to accept being
permanently `ahead` on one carried file (SC1 unreachable forever) or to route the routine case
through `[skip-sdlc-sync]` (the failure this repository already fixed once). Both were rejected.

The review found the consequence this section had not followed through: the carried
`docs/sdlc.md` says, twice, that a process change must update "this file" — so after PR 2 the
shared document would instruct every reader and every agent to edit the wrong one, and this
repository could not correct it locally without becoming `ahead`. **PR 0, Task 4 fixes it
upstream**, making both sentences name `process.doc`. That is the right place: the correction is
true for every consumer, including one where `process.doc` *is* `docs/sdlc.md`, so the carried
document gets more general rather than less.

## Design notes the tasks assume

Six points that are load-bearing.

**1. The conformance check cannot execute a real repository's targets.** Its second assertion runs
`./verify.sh "$t"` once per declared target and calls any exit status other than 64 a pass. Against
the toolkit's skeleton every target is `not_implemented` and exits 2 immediately, so the cost is
nothing. Against *this* repository it would run `npm ci`, `npm audit`, eslint, prettier, `tsc`,
Vitest, `vite build`, three `docker build`s, `terraform init`, `terraform validate` and a database
migration — inside the `SDLC docs` metadata job, on every pull request. PR 0 replaces that
assertion with a `--targets` introspection arm: the script prints the set it knows, the check
compares it to the declaration, and nothing is executed. That is both cheaper and **stronger** — it
also catches a target the script has that the config does not declare, which the old form could
not see.

**2. After PR 0 the check runs each `verify.sh` three times, and every run exits immediately.**
Once with `--targets`, which prints and stops; once with `__no_such_target__`, where dispatch
falls through to `exit 64`; and once with a `false` planted as the **first statement** of the
first declared target's body. Choosing `install` for backend and frontend and `selftest` for infra
is what keeps that last run free: `false` fires before `npm ci` or the gate suites do anything.
Three immediate exits per component replaces nine, seven and five full target runs.

**3. Function discovery must agree with the plant, or the check passes vacuously.** The old plant
searched for `target_<name>() {` and silently inserted nothing when the name was different — an
assertion that then passed because the script exited non-zero for an unrelated reason. PR 0 makes
discovery return the exact prefix the plant matches, and adds a `cmp` that fails loudly when the
patched copy is identical to the original. That second guard is the one that matters: it is
independent of which naming convention wins.

**4. A one-line function body defeats a naive plant.** `install() { run npm ci; }` is a complete
definition on one line. Printing `false` on the line *after* it lands outside the body, at file
scope, where it runs at definition time and aborts the script before dispatch — non-zero exit, for
entirely the wrong reason. The plant therefore injects **inside the opening brace**
(`{` → `{ false;`), which is correct for both shapes and needs no special case.

**5. `acb status`'s drift check assumes every component job lives in `ci.yml`.** It does not here:
`Terraform checks` has its own workflow because the Terraform toolchain setup does not belong in
the middle of the Node pipeline, and `Deploy scripts` will have its own for the same kind of
reason. PR 0 makes the check read every `.github/workflows/*.yml`, and demotes "a job nothing
requires" from an error to a note — because a non-gating workflow is normal, and this repository
already has one (`Dependabot auto-merge`).

**6. The ruleset document is generated-bucket, which means it is ours.** `acb init` would render it
once; this repository is not being `init`-ed, it is being adopted. PR 3 writes
`.github/ruleset.json` by hand to reproduce the **live** ruleset (D2), including the sixth check,
and `scripts/apply-ruleset.sh` is copied from the template unchanged. No schema change is needed to
express `Deploy scripts` — a consumer-owned file does not need the generator's permission.

- [ ] **Step 4: Rewrite the check.** Replace `carried/scripts/check-conformance.sh` in full:

```bash
#!/usr/bin/env bash
# Proves the verify.sh contract holds for every declared component. It tests the script's
# PLUMBING, never its checks — which is what makes it stack-agnostic: dispatch, exit codes and
# error propagation are identical in a Swift repository and a Terraform one, while the checks
# themselves have nothing in common.
#
# It runs each verify.sh three times — `--targets`, an unknown target, and one real target with a
# `false` planted as its first statement — and every one of the three exits immediately. Asking
# "does target X dispatch?" by RUNNING target X was the first design and it is wrong for any repository
# whose targets do something: it re-runs the install, the build and the image push inside a
# metadata job on every pull request. The known-target set is read through `--targets` instead,
# which is also stronger — it sees a target the script has and the declaration does not.
set -uo pipefail
cd "$(dirname "$0")/.." || exit 1

ACB_CONFIG="${ACB_CONFIG:-.acb.json}"
if [[ ! -f "$ACB_CONFIG" ]]; then
  echo "✗ no $ACB_CONFIG — this check needs one." >&2
  exit 1
fi

pass=0; fail=0
ok()  { pass=$((pass + 1)); printf '  ✓ %s\n' "$1"; }
bad() { fail=$((fail + 1)); printf '  ✗ %s — %s\n' "$1" "$2"; }

# One trap for the whole run. A trap set inside the loop is replaced on every iteration, so all
# but the last patched copy would survive a failure.
trap 'rm -f ./*/.acb-conformance.sh' EXIT

# The function implementing a target, by the three conventions a real script uses, in this fixed
# and documented order: the skeleton's own prefix; the trailing underscore a script adopts to
# dodge a shell builtin (`test`); the plain name.
#
# It returns the exact string the plant below searches for, not just the name — so discovery and
# patching cannot disagree about what they matched, which is how the plant came to insert nothing
# while the assertion still reported a pass.
target_fn_prefix() {
  local script="$1" name="$2" cand
  for cand in "target_$name" "${name}_" "$name"; do
    if awk -v fn="$cand() {" 'index($0, fn) == 1 { found = 1 } END { exit !found }' "$script"; then
      printf '%s() {\n' "$cand"
      return 0
    fi
  done
  return 1
}

for id in $(jq -r '.components[]?.id' "$ACB_CONFIG"); do
  v="$id/verify.sh"

  # 1. It exists and is executable.
  if [[ -x "$v" ]]; then ok "$id: verify.sh is executable"
  else bad "$id: verify.sh is executable" "missing or not +x"; continue; fi

  # 2. The script's own target list and the declaration agree, in BOTH directions. A declared
  #    target the script does not know is a CI step that cannot run; a target the script knows and
  #    nothing declares is a check nobody calls. Read, never executed.
  declared="$(jq -r --arg i "$id" '.components[]|select(.id==$i)|.targets[]' \
              "$ACB_CONFIG" | LC_ALL=C sort)"
  actual="$( ( cd "$id" && ./verify.sh --targets ) 2>/dev/null | LC_ALL=C sort )"
  if [[ -z "$actual" ]]; then
    bad "$id: --targets agrees with the declaration" \
        "./verify.sh --targets printed nothing — the script does not implement it"
  elif [[ "$declared" == "$actual" ]]; then
    ok "$id: --targets agrees with the declaration"
  else
    bad "$id: --targets agrees with the declaration" \
        "declared [$(echo "$declared" | tr '\n' ' ')] vs --targets [$(echo "$actual" | tr '\n' ' ')]"
  fi

  # 3. An undeclared target is rejected, and rejected distinguishably. Exit 64 means "unknown
  #    target"; 2 is "declared but not implemented yet", and one shared code makes this vacuous.
  ( cd "$id" && ./verify.sh __no_such_target__ >/dev/null 2>&1 ); rc=$?
  if [[ $rc -eq 64 ]]; then ok "$id: unknown target exits 64"
  else bad "$id: unknown target exits 64" "got $rc"; fi

  # 4. A failure inside a target propagates to the script's exit status.
  #
  #    Be precise about what this proves, because the tempting overclaim is wrong. It plants a
  #    `false` as the first statement of the target body and requires a non-zero exit. That
  #    catches the two structural ways a target can become unable to fail: a body running without
  #    `errexit`, where an early failure is ignored and a later success sets the status; and a
  #    dispatcher that swallows the target's status (`"target_$1" || true`).
  #
  #    It does NOT prove an individual check can fail. `grep -q x file || true` inside the body
  #    still exits 0 on its own, and this assertion will not see it — detecting that needs
  #    mutation of the checks themselves, which is a different tool. Reviewers catch those; this
  #    catches the plumbing that would silence all of them at once.
  #
  #    The FIRST declared target is used, and being first is what keeps this cheap: `false` fires
  #    before the body's real work starts, so the run costs nothing however heavy the target is.
  #
  #    The patched copy is written INSIDE the component directory, not in /tmp. The script's own
  #    `cd "$(dirname "$0")"` is what makes its relative paths work, so a copy elsewhere would run
  #    the target against the wrong directory and prove nothing. The original is never written to.
  first="$(jq -r --arg i "$id" '.components[]|select(.id==$i)|.targets[0]' "$ACB_CONFIG")"
  if ! prefix="$(target_fn_prefix "$v" "$first")"; then
    bad "$id: a failure inside '$first' propagates" \
        "no function implements it — tried target_${first}(), ${first}_() and ${first}(). Name it one of those."
    continue
  fi
  tmp="$id/.acb-conformance.sh"
  # Injected INSIDE the opening brace, not printed on the following line. `install() { run npm ci; }`
  # is a complete definition on one line, and a `false` printed after it lands at file scope: it
  # runs at definition time and aborts the script before dispatch — a non-zero exit for entirely
  # the wrong reason. Rewriting the brace is correct for both shapes and needs no special case.
  awk -v fn="$prefix" '
    !done && index($0, fn) == 1 { sub(/\{/, "{ false;"); done = 1 }
    { print }
  ' "$v" > "$tmp"
  # The plant must have changed something. This is the guard that holds however the naming
  # conventions evolve: a patch that silently inserts nothing produces an assertion that passes
  # vacuously, which is the exact defect this check exists to catch and has exhibited once.
  if cmp -s "$v" "$tmp"; then
    bad "$id: a failure inside '$first' propagates" "the planted 'false' changed nothing"
    continue
  fi
  chmod +x "$tmp"
  ( cd "$id" && "./$(basename "$tmp")" "$first" >/dev/null 2>&1 ); rc=$?
  if [[ $rc -ne 0 ]]; then ok "$id: a failure inside '$first' propagates"
  else bad "$id: a failure inside '$first' propagates" "exit 0 with a planted 'false'"; fi
done

printf '\n%d passed, %d failed\n' "$pass" "$fail"
[[ "$fail" -eq 0 ]]
```

## Rollback

Each pull request is separately reversible, and the order is the reverse of the order they landed.

| Landed | To undo | Cost |
| --- | --- | --- |
| PR 3 | `gh api --method PUT … --input .acb-rollback/ruleset-before.json` (in the **main checkout**), then revert the commit | Minutes. The ruleset is the only non-file state. |
| PR 2 | Revert the merge commit. `ACB_DEPENDABOT_ECOSYSTEMS` may stay — the old workflow ignores it. | One revert. The three new documents are additive and can stay. |
| PR 1 | Revert the merge commit. | One revert. Nothing outside this repository depends on the names. |
| PR 0 | Revert in `acb`. This repository is unaffected until it pulls. | One revert, one repository. |

The one thing that is **not** cheaply reversible is the sixth required check while pull requests
are open: removing `Deploy scripts` from the ruleset is one API call, but any pull request opened
in between will have been evaluated against six checks. That is a minutes-scale inconvenience, not
a data risk.

## Blast radius

Everything in this plan is inside two repositories that only I use, and nothing it touches is
deployed — the GCP environment has been torn down since 2026-08-25. The worst case is that
`main` becomes unmergeable because a required check name and a job name disagree, which the
rollback row above fixes with one API call. No user data, no secret, and no running service is in
scope.
